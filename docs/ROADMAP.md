### 착수 순서 (확정)

우선순위표(위)는 **중요도** 순. 실제 만드는 순서는 **의존성** 순으로 다름.

| 순서 | 작업 | 왜 이 순서인가 |
|---|---|---|
| **0** | 프로젝트 셋업 + 데이터 레이어<br>`lib/types.ts` · `lib/data.ts` · `lib/slug.ts` | 전 기능이 여기 의존. 문자열 필드 정규화(`"5 Slash"` → `{slash:5}`)도 여기서 한 번에 |
| **1** | `/db/items` 아이템 도감 | 가장 단순한 소비자 → **데이터 레이어 검증용**. 동시에 디자인 시스템·공용 컴포넌트가 여기서 확립됨 |
| **2** | `/about` 법적 고지 | 분량 적음. 일찍 배포해두면 애드센스 심사 조건 미리 충족 |
| **3** | `/db/creatures` · `/db/bosses` | 1번과 같은 패턴 반복이라 빠름. 여기까지 하면 **정적 페이지 100개+ 확보** → 검색 색인 시작 |
| **4** | `/calc/drop` 드롭률 시뮬레이터 | 계산기 중 가장 단순(확률 계산뿐). **계산기 UI 패턴을 여기서 확립** |
| **5** | `/calc/food` 음식 계산기 | 중간 난이도. 3슬롯 조합 + 최적화 로직 |
| **6** | `/calc/build` 제작·건축 계산기 | **가장 복잡** (재귀 재료 전개, 보유량 차감, 장바구니). 앞의 컴포넌트 최대한 재사용 |
| **7** | 홈 (계산기 허브 + 통합 검색) | **마지막.** 허브는 무엇을 링크할지 다 정해진 뒤에 만들어야 두 번 안 만듦 |

**핵심 판단 근거 3가지**

1. **도감 먼저, 계산기 나중** — 도감이 데이터 레이어를 검증해주고 공용 컴포넌트를 만들어줌.
   계산기부터 시작하면 데이터 문제를 복잡한 로직 속에서 디버깅하게 됨.
2. **SEO 색인은 시간이 걸림** — 정적 페이지 100개를 3번 단계에서 일찍 띄워두면
   9/9 출시 시점엔 이미 색인이 돌아간 상태. 계산기는 나중에 붙어도 됨.
3. **쉬운 계산기 → 어려운 계산기** — 드롭률(단순) 단계에서 계산기 UI 패턴을 확립하고,
   제작 계산기(복잡)에서 그걸 재사용. 반대로 하면 패턴을 두 번 만듦.

**중간 배포 시점**: 3번 완료 시 1차 배포 + 애드센스 신청. 6번 완료 시 2차 배포.

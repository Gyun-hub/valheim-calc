## 1. 정책·저작권 문제

### 1-1. 공식 팬 콘텐츠 정책
- Iron Gate EULA 3.6조에 "Content Usage Guidelines"라는 별도 문서 존재를 언급하지만, 실제 공개된 문서 링크는 **찾지 못함**. Riot Games("Legal Jibber Jabber"), Mojang("Usage Guidelines")처럼 명문화된 공개 가이드라인이 있는 대형 퍼블리셔와 달리, Iron Gate는 소규모 스튜디오라 이 부분이 불투명함.
- "Regarding Mods" 공식 글은 있음 (모드 유료화 반대, 비공식 표기 요구) — 단 이는 게임 내 모드 대상이지 웹사이트 대상 아님.

### 1-2. EULA상 실제 제약 (원문 확인)
- **5.2.3조**: 게임 수정/파생물 생성 금지
- **5.2.4조**: 사전 서면 동의 없는 "공적/상업적 이용" 금지
- **5.2.5조**: 리버스 엔지니어링/디컴파일 금지
- **4.1조 (허용 목록)**: 스크린샷, 플레이 영상 SNS 공유, 트위치/유튜브 광고 수익화, Patreon 독점 콘텐츠는 명시적으로 허용. **에셋 파일(텍스처/모델/사운드) 자체를 추출해 재게시하는 행위는 이 허용 목록에 없음** → 회색지대~금지 영역으로 해석하는 게 안전.

### 1-3. 실제 집행 사례
- Iron Gate가 팬 위키/계산기/유튜브에 DMCA나 C&D를 보낸 사례 **전무** (조사 범위 내).
- 오히려 공식 사이트(valheimgame.com) 푸터에서 Fandom 위키를 직접 링크 — Fandom은 광고 수익 플랫폼인데도 묵인.
- valculator.io, valheim.tools, kirilloid 계산기 등 계산기 사이트들도 장기간 무탈 운영 중.

### 1-4. 실무 원칙 — 무엇이 안전하고 무엇이 위험한가
| 안전 | 위험 |
|---|---|
| 아이템 스탯/레시피/드롭률 수치를 직접 표로 재구성 | 게임 파일에서 뽑은 텍스처/아이콘 이미지를 그대로 올리기 |
| 직접 플레이하며 찍은 스크린샷 | 3D 모델/사운드 파일 추출해 배포 |
| 직접 그린 일러스트/아이콘 | 게임 로고, 공식 마케팅 이미지 무단 사용 |
| "비공식 팬 사이트" 명시 | 공식 서비스로 오인될 소지 있는 디자인/브랜딩 |

### 1-5. 광고 수익화 영향
EULA 문언상 "상업적 이용" 자체가 이미 제약 대상으로 명시되어 있어, 무료냐 광고 수익화냐를 문언으로 구분하진 않음. 그러나 실제 집행 사례가 없고 Fandom(광고 기반)을 공식 링크한 정황상, **핵심 트리거는 광고 여부가 아니라 "에셋을 무단으로 대량 사용했는가"**로 보임.

### 1-6. 권고
1. 이미지는 전부 직접 제작 (아이콘 새로 그리기 or 직접 스크린샷)
2. 데이터(수치)는 자유롭게 재구성해서 사용
3. 사이트 어딘가에 "비공식 팬 사이트, Iron Gate/Coffee Stain과 무관" 명시
4. **가장 확실한 방법**: Iron Gate에 사전 이메일 문의 (contact@irongatestudio.se) — 법적 자문은 아니지만 리스크 사실상 제거
5. 로고/공식 아트워크는 쓰지 말 것

## 2. 기존 위키·데이터 현황

### 2-1. 주요 기존 위키
| 사이트 | 성격 | 라이선스 |
|---|---|---|
| valheim.fandom.com | 사실상 공식 위키 (Iron Gate가 직접 링크), 매우 활발 | **CC BY-SA 3.0** (텍스트) — 재사용 시 출처 표시 + 동일 라이선스 재배포 의무 |
| valheim.miraheze.org | 커뮤니티 대체 위키 | 추정 CC BY-SA 4.0 (미확인) |
| valheim-wiki.com | 커뮤니티 운영 | 불확실 |
| valheim.kirilloid.ru | 개인 제작, DB+계산기 하이브리드 | 비영리 명시 (상업적 재사용 부적합 신호) |

**중요**: CC BY-SA는 "위키 기여자가 작성한 편집물"에 적용되는 것이지, 게임사 소유인 게임 원본 텍스트/아이콘 저작권까지 무효화하진 않음. 그대로 복붙하지 말고 참고해서 직접 재작성 권장.

### 2-2. API 접근
Fandom 위키는 표준 **MediaWiki API**(`api.php`) 제공 → 프로그래밍적 데이터 수집 가능. 단, 인포박스 구조화 데이터 파싱은 위키별 템플릿 구조 분석이 추가로 필요함.

### 2-3. GitHub 오픈소스 데이터
| 저장소 | 내용 | 비고 |
|---|---|---|
| kirilloid/valheim | 아이템 DB, 계산기 데이터 | 비영리 명시, 상업 재사용 부적합 |
| XanderG2/valheim-stats | 무기/방어구 스탯 JSON | Fandom 위키 스크래핑 기반 (라이선스 승계 문제), **Ashlands 이전 버전에서 방치됨** |
| ASharpPen/Valheim.DropThat | 몬스터 50종+ 드롭률/수량 데이터 | 2021년 자료, 최신 반영 여부 불확실 |
| Valheim-Modding/Jotunn | 게임 데이터 자동생성 프리팹/아이템 목록 | 아이템 ID 체계 참고용 |

**핵심**: 조사된 데이터 프로젝트 대부분이 결국 Fandom 위키 스크래핑이거나 게임파일 리버스엔지니어링. "게임사 공식 데이터 배포"는 존재 안 함.

### 2-4. 확률(드롭률) 데이터 신뢰성
Iron Gate는 확률 수치를 **공식 발표한 적 없음**. 현재 유통되는 확률은:
1. 커뮤니티 반복 플레이 실측 추정 (방법론 불명, 참고용)
2. 데이터마이닝/리버스엔지니어링 (게임 로직에 가까움, 신뢰도 상대적으로 높으나 업데이트 지연 위험)

→ 계산기 만들 때 확률 데이터가 가장 약한 고리. "커뮤니티 추정치" 임을 명시하고 다중 소스 교차검증 권장.

## 3. 계산기/시뮬레이터 뭘 만들까

### 3-1. 초대형 변수: 2026년 9월 9일 = Valheim 1.0 + Deep North 정식 출시
PC Gaming Show(2026-06)에서 공식 발표. PS5/Switch 2 동시 출시로 신규 유저 유입까지 예상. 기존 계산기 사이트들은 업데이트 반영에 시차 있는 경향 확인됨 (XanderG2 계산기가 Ashlands 이전 버전에서 그대로 방치된 게 대표 사례).

**→ 출시일에 맞춰 Deep North 데이터를 가장 먼저 반영한 사이트를 내놓으면, 트래픽 선점 효과가 상당할 것으로 보임.** 지금(7월 말)부터 개발 시작하면 딱 맞는 타이밍.

### 3-2. 이미 포화된 카테고리 (진입 비추천)
- 시드맵/월드 뷰어 (5개 이상 경쟁)
- 빌드 자원 계산기 (Valculator, XGamingServer, valheim.tools 등 다수)
- 음식/버프 계산기 (5개 이상)
- 무기 데미지/DPS 계산기 (3개 이상, 정확도 이미 높음)

### 3-3. 존재하지만 구식/저품질 (개선 여지)
- XanderG2 계산기: Ashlands 이전 데이터로 방치
- BuildShare 모드: 1년 이상 방치
- 구글시트 기반 툴들: UX 낙후, 모바일 대응 부족, 일부 유료 장벽

### 3-4. 완전 공백 — 경쟁 도구 없음 (최우선 추천)
1. **길들이기/번식 계산기** — 별등급 유전 확률, 번식 타이머, 개체수 한계. 규칙 명확해서 구현 난이도 낮음.
2. **멀티플레이 스케일링 계산기** — 파티 인원수 입력 → 보스/몹 실효 체력·데미지 산출 (게임 내부 공식: +30%/인, 100m 반경). 단순 수식이라 구현 쉬움.
3. **항해/바람 경로 플래너** — 바람 방향/강도 기반 최적 항로·출항 타이밍. 구현 난이도 중상(물리 모델링 필요)이지만 경쟁 전무.
4. **마법(Eitr)/스탭 빌드 계산기** — 장비 조합별 Eitr 재생량, 스펠 지속캐스팅 가능 횟수. 엔드게임 유저 타겟, 충성도 높은 소규모 수요.
5. **포탈 제한재료 패킹 리스트** — 인벤토리 입력 → 포탈 통과 가능/불가 자동 분류. 기존 자원계산기에 애드온으로 붙이기도 좋음.

### 3-5. 커뮤니티 실제 불만 (Reddit/Steam 확인)
- 아이템 검색 기능 부재 ("여러 상자에 흩어진 재료 찾기 힘들다")
- 멀티플레이 스케일링 이해 어려움 (텍스트 설명만 있고 계산기 없음 — 위 3-4의 2번과 일치)
- 지형 정리 없이 블루프린트 앉히기 어려움 (BuildShare 방치로 대안 부족)

### 3-6. 바이럴/공유형 콘텐츠 (실험적, 확신도 낮음)
"당신은 어떤 바이킹?" 퀴즈, 결과 공유 카드 같은 재미 중심 포맷은 **발헤임 생태계에 전혀 없음**. 확정 근거는 약하지만, 시드맵 뷰어류가 PCGamer/GamesRadar 등 매체 커버리지를 받은 전례(탐색+발견 재미 요소가 화제성 있음)로 볼 때, 소규모로 시도해볼 가치는 있음. 트래픽 유입 채널로 활용 가능.

### 3-7. 한국어 시장 특수성 — 전략 수정 (중요 발견)
기존 3-2~3-4 분석은 전부 **영어권 사이트 기준**. 한국어 시장을 직접 확인한 결과:
- 나무위키에 발헤임 텍스트 공략은 존재함 (`Valheim/세계`, `Valheim/자원`, `Valheim/탈 것` 등 문서)
- 그러나 **한국어로 된 인터랙티브 계산기/시뮬레이터형 사이트는 검색상 확인되지 않음** — 사실상 공백

**결론: 타겟을 한국어 사용자로 잡으면, 영어권에서는 "포화"로 분류한 자원 계산기/음식 계산기/데미지 계산기 카테고리도 한국어 시장에서는 사실상 블루오션.** 언어 장벽이 곧 진입장벽 역할을 해줌.

수정된 전략:
1. 영어권처럼 굳이 틈새 카테고리(3-4)부터 시작할 필요 없음 — 기본 계산기(자원/음식/데미지)부터 한국어로 만들어도 경쟁 없음
2. 3-4의 공백 카테고리(길들이기, 멀티플레이 스케일링, 항해, 마법 빌드)를 추가하면 영어권 사이트 대비로도 차별화됨
3. SEO 타겟 키워드 명확 — "발헤임 계산기", "발헤임 자원 계산", "발헤임 음식 계산기" 등 한국어 키워드는 경쟁 사이트가 없어 상위노출 유리
4. 나무위키는 텍스트 위키형이라 계산기 UX를 제공하지 않음 — "인터랙티브 계산기"라는 형식 자체가 나무위키 대비 명확한 차별점

## 4. 내가 못 챙긴 것 같은 부분 (권고)

1. **타이밍이 핵심 변수임을 놓치고 있었을 가능성** — 9월 9일 1.0/Deep North 출시는 이 프로젝트의 성패를 가를 수 있는 요소. 지금 스택 잡고 8월 안에 기본 틀 완성 → 출시일에 맞춰 데이터 업데이트하는 일정으로 짜는 게 유리함.
2. **이미지 제작 부담 과소평가 위험** — 발헤임 아이템만 800종 이상. 전부 직접 그린 아이콘으로 대체하려면 상당한 리소스. 대안: (a) 처음엔 텍스트/수치 중심 계산기로 시작해 이미지 의존도 낮추기, (b) 필요한 것만 소수 직접 제작, (c) 오픈소스 게임 아이콘팩 스타일로 재해석해서 그리기.
3. **애드센스 심사 리스크** — 저작권 침해 소지 있는 이미지가 많으면 애드센스 승인 자체가 반려될 수 있음. 위 1번 정책 권고(직접 제작)를 지키는 게 수익화 측면에서도 중요.
4. **유지보수 부담 = 1회성 프로젝트 아님** — 게임이 계속 업데이트되는 라이브 서비스라, 계산기 데이터도 지속 갱신 필요. 크몽 포트폴리오용 "양산형 데모"와는 성격이 다름 — 이건 장기 운영 프로젝트가 됨. 시간 투자 각오 필요.
5. **종합 위키로 valheim.tools와 정면승부는 비추천** — 이미 아이템 807종, 크리처 103종급 데이터베이스를 갖춘 경쟁자 있음. 처음부터 "종합 위키"가 아니라 위 3-4의 틈새 계산기 1~2개로 시작해서 트래픽 확보 후 확장하는 게 현실적.
6. **상표권 이슈 별도 고려** — 사이트명에 "Valheim" 그대로 넣는 것 자체는 팬 사이트 관행상 흔하지만("Valheim Wiki", "Valheim Calculator" 등 기존 사례 다수), 로고나 공식 폰트/디자인 그대로 베끼는 건 피할 것.
7. **Reddit 데이터는 조사 한계 있음** — r/valheim 직접 크롤링이 막혀 있어 이번 조사는 Steam 포럼/검색엔진 스니펫으로 대체함. 실제 착수 전 Reddit 상위 게시물 직접 확인 권장 (수요 검증 보강용).
